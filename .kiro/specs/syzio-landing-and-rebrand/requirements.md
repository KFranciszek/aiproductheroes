# Requirements Document - Syzio Landing Page & Rebrand

## Introduction

This document outlines the requirements for transforming BrainTask into **Syzio** - a next-generation project management platform for IT teams. The transformation includes:

1. **Complete rebrand** from BrainTask to Syzio with new visual identity based on astronomical syzygy metaphor
2. **New landing page** that tells the Syzio story and showcases the product's unique value proposition
3. **Demo mode** - converting the existing application into an interactive demo accessible from the landing page
4. **Three pillars philosophy** - Team Syzio, Tool Syzio, and Sprint Syzio as core product differentiators

### Core Concept

**Syzygy** (astronomy): When 3+ celestial bodies align perfectly - a rare moment of cosmic harmony.

**Syzio** (product management): Perfect alignment of Team, Tools, and Time - eliminating chaos in IT project management.

---

## Requirements

### Requirement 1: Brand Identity & Visual System

**User Story:** As a visitor, I want to immediately understand that Syzio represents perfect alignment and harmony, so that I connect with the product's core philosophy.

#### Acceptance Criteria

1. WHEN a user visits the site THEN they SHALL see a cohesive visual system based on astronomical/celestial themes
2. WHEN viewing any page THEN the design SHALL use modern, tech-forward aesthetics that reflect current market trends
3. IF the user interacts with UI elements THEN they SHALL experience smooth animations representing celestial movement and alignment
4. WHEN viewing the logo THEN it SHALL visually represent the concept of three bodies aligning (Team, Tool, Time)
5. WHEN reading any copy THEN the tone SHALL be tech-forward, modern, and professional without being overly casual

**Design Elements:**
- Color palette inspired by space/astronomy (deep blues, purples, cosmic gradients)
- NOT the previous green theme (#9be5a1)
- Typography: Modern, clean, tech-forward
- Iconography: Celestial bodies, orbits, alignment symbols
- Animations: Orbital movements, alignment sequences, gravitational effects

### Requirement 8: Landing Page - Newsletter Signup

**User Story:** As an interested visitor, I want to sign up for updates about Syzio, so that I can stay informed about the product launch and features.

#### Acceptance Criteria

1. WHEN a user views the landing page THEN they SHALL see a newsletter signup form
2. WHEN filling out the form THEN they SHALL provide:
   - Email address (required)
   - Company name (optional)
   - Team size (optional dropdown: 2-10, 11-50, 51-200, 200+)
3. WHEN submitting the form THEN they SHALL see a success message: "🌕 You're on the path to perfect syzio!"

### Requirement 9: Demo Mode - Entry Point

**User Story:** As a visitor who clicked "Try Demo", I want to experience Syzio's features interactively, so that I can evaluate if it fits my needs.

#### Acceptance Criteria

1. WHEN a user clicks "Try Demo" on the landing page THEN they SHALL be taken to `/demo` route
2. WHEN entering demo mode THEN they SHALL see the existing application with:
   - "Syzio" name (replacing "BrainTask")
   - All existing features and UI unchanged
   - Pre-populated sample data (existing mock data)
3. WHEN using the demo THEN they SHALL see a minimal header addition:
   - "Demo Mode" badge (small, non-intrusive)
   - "← Back to Home" link
4. IF the user makes changes in demo THEN they SHALL be saved to localStorage (existing behavior)

### Requirement 10: Demo Mode - No Tutorial (Out of Scope)

**User Story:** As a demo user, I want to freely explore the application without guided tutorials.

#### Acceptance Criteria

1. WHEN a user enters demo mode THEN they SHALL immediately see the application
2. WHEN using the demo THEN there SHALL be NO onboarding tooltips or tutorials
3. WHEN exploring features THEN the user SHALL discover functionality organically

**Note:** Onboarding tutorial is OUT OF SCOPE for this phase. Users explore the existing application freely.

---

### Requirement 11: Rebrand - Name Change Only

**User Story:** As a user of the demo, I want to see the Syzio name throughout the application, so that the branding is consistent.

#### Acceptance Criteria

1. WHEN viewing the application THEN "BrainTask" SHALL be replaced with "Syzio" everywhere
2. WHEN viewing the logo THEN it SHALL display "Syzio" 
3. WHEN viewing page titles THEN they SHALL reference "Syzio"
4. WHEN viewing the README THEN it SHALL be updated to "Syzio"

**Note:** Only the name changes. All existing terminology (Sprints, Dashboard, Issues, etc.) remains the same.

---

### Requirement 12: Demo Mode - Minimal Changes

**User Story:** As a demo user, I want the existing application to work as-is with just the Syzio name, so that I can evaluate the current functionality.

#### Acceptance Criteria

1. WHEN viewing the demo application THEN it SHALL maintain all existing:
   - Color scheme (current green theme)
   - Layout and components
   - Features and functionality
   - User interface elements
2. WHEN entering demo mode THEN the ONLY change SHALL be the name "Syzio" replacing "BrainTask"
3. WHEN using the demo THEN all existing features SHALL work identically to the current application

**Note:** Visual rebrand and celestial theme are OUT OF SCOPE for the demo. Focus is on the landing page only.

**User Story:** As a visitor, I want clear navigation and access to important links, so that I can easily find information and contact the team.

#### Acceptance Criteria

1. WHEN viewing the landing page THEN the navigation SHALL include:
   - Logo (links to home)
   - Features
   - How It Works

   - Try Demo

   - Product links: Features, Demo, Roadmap

4. IF a link is a placeholder THEN it SHALL show a tooltip: "Coming soon"

### Requirement 14: Landing Page - Responsive Design

**User Story:** As a mobile user, I want the landing page to work perfectly on my device, so that I can explore Syzio on the go.

#### Acceptance Criteria

1. WHEN viewing on mobile (< 768px) THEN the layout SHALL stack vertically
2. WHEN viewing the hero on mobile THEN the animation SHALL be simplified for performance
3. WHEN viewing the three pillars on mobile THEN they SHALL be displayed as a carousel or stacked cards
4. WHEN opening the navigation on mobile THEN it SHALL show a hamburger menu
5. IF the user rotates their device THEN the layout SHALL adapt smoothly

---

### Requirement 15: Landing Page - Performance & SEO

**User Story:** As a visitor, I want the landing page to load quickly and be discoverable in search engines, so that I have a smooth experience and can find Syzio easily.

#### Acceptance Criteria

1. WHEN the page loads THEN it SHALL achieve:
   - Lighthouse Performance score > 90
   - First Contentful Paint < 1.5s
   - Largest Contentful Paint < 2.5s
2. WHEN search engines crawl the page THEN they SHALL find:
   - Proper meta tags (title, description, og:image)
   - Semantic HTML structure (h1, h2, nav, main, footer)
   - Alt text for all images
3. WHEN sharing on social media THEN it SHALL show:
   - Syzio logo as og:image
   - Compelling description
   - Proper title
4. IF animations are heavy THEN they SHALL use CSS transforms and will-change for GPU acceleration

---

### Requirement 16: Demo Mode - Exit & Conversion

**User Story:** As a demo user who's impressed, I want clear paths to sign up or contact sales, so that I can move forward with Syzio.

#### Acceptance Criteria

1. WHEN using the demo THEN the user SHALL see periodic CTAs:
   - After 5 minutes: "Loving Syzio? Get early access"
   - After completing tutorial: "Ready for your team's syzio?"
   - When exiting: "Don't lose your alignment - sign up for updates"
2. WHEN clicking a CTA THEN they SHALL see a modal with:
   - Email signup form
   - "Request Demo for My Team" option
   - "I'm just exploring" (dismisses)
3. WHEN exiting demo mode THEN they SHALL see an exit survey:
   - "What did you think?" (1-5 stars)
   - "What feature impressed you most?" (optional text)
   - "Would you recommend Syzio?" (Yes/No)
4. IF the user provides feedback THEN it SHALL be stored in localStorage

---

### Requirement 17: Technical Architecture - Routing

**User Story:** As a developer, I want clear separation between landing page and demo mode, so that the codebase is maintainable and scalable.

#### Acceptance Criteria

1. WHEN the application loads THEN it SHALL use Next.js App Router with routes:
   - `/` - Landing page
   - `/demo` - Demo mode (existing BrainTask app)
   - `/demo/onboarding` - Tutorial flow
2. WHEN navigating between routes THEN transitions SHALL be smooth with loading states
3. WHEN in demo mode THEN the URL SHALL reflect the current view (e.g., `/demo/issues`, `/demo/sprints`)
4. IF the user refreshes in demo mode THEN they SHALL stay in demo mode with state preserved

---

### Requirement 18: Technical Architecture - Data Isolation

**User Story:** As a developer, I want demo data to be isolated from any future production data, so that users can experiment freely without consequences.

#### Acceptance Criteria

1. WHEN a user enters demo mode THEN all data SHALL be stored with a `demo_` prefix in localStorage
2. WHEN the user exits demo THEN they SHALL have the option to "Reset Demo Data"
3. WHEN demo data is reset THEN it SHALL reload the default sample project
4. IF the user signs up for real access THEN demo data SHALL NOT interfere with their production workspace

## Success Metrics

### User Engagement
- Time spent on landing page > 2 minutes (indicates interest)
- Demo mode entry rate > 30% of landing page visitors
- Newsletter signup rate > 10% of visitors
- Demo completion rate > 50% (complete onboarding tutorial)

### Brand Perception
- Visitors understand the "syzygy" concept (measured via exit survey)
- "Tech-forward" and "modern" mentioned in qualitative feedback
- Social media shares using #SyzioAchieved, #TeamSyzio

### Technical Performance
- Landing page Lighthouse score > 90
- Demo mode loads in < 2 seconds
- Zero console errors in production
- Mobile responsiveness score 100%

## Out of Scope (Future Phases)

The following are explicitly NOT included in this phase:

- ❌ Real backend/database (using localStorage for demo)
- ❌ User authentication/accounts
- ❌ Payment/pricing implementation
- ❌ Real integrations with GitHub/Slack/etc.
- ❌ Multi-language support
- ❌ Blog/content management system
- ❌ Customer support chat
- ❌ Analytics dashboard for admins
- ❌ Mobile native apps

These will be addressed in future phases after validating the core concept with users.
